# Code Review Checklist

- [ ] Design fits the system.
- [ ] Functionality is correct and useful.
- [ ] Complexity is no higher than necessary.
- [ ] Tests are appropriate and would fail if behavior broke.
- [ ] Names communicate intent.
- [ ] Comments explain why, not obvious what.
- [ ] Style matches the project.
- [ ] Docs were updated for changed setup, build, release, or user behavior.
- [ ] Security, privacy, data-loss, migration, and concurrency risks were checked.
- [ ] Nits are marked as `Nit:` and do not block approval.
